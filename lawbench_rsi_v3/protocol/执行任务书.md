# LawBench Harness RSI：四项预实验执行任务书（v3，100题评分版）

## 0. 交付目标与权限

执行 agent 的任务是：在用户提供的 `text_classificition.zip` 的独立副本里修改并测试代码，依次完成下面四项实验，汇总结果，回答“额外反馈 D 是否有效、追加轮数 T 是否有效、有限配置是否能预测未运行的中间配比”。这不是让 agent 再讨论方案或自行换题。保留四个实验、R4B起点、每轮两个候选、相同模型；废弃旧20题评分/30题反馈的预实验划分。

本包提供的是可交付执行 agent 的任务书、数据准备脚本及其离线测试，不是已经完成的真实模型实验，也不含完成后的结果。`prepare_data.py` 可以独立执行；付费实验驱动器、代码补丁及分析程序需要执行 agent 按本任务书实现、自测后运行。用户提供的API/CLI认证仅在本地使用，不读取或写入报告中的密钥。

不调用 `--fresh`，不修改或删除旧归档、旧候选、旧日志和旧缓存，不推送Git远程。修改在新工作目录进行。已有文档和旧manifest只存档，不把旧文件覆盖成新含义。执行所需凭据不可用时，输出具体缺项并暂停，不能擅自更换模型或服务商。总预算上限由用户在 `pilot_config.json` 中确认后执行；推荐预留100美元“日志估值口径”的上限，报告中不要称它为订阅用户的实际现金支出。预算不足时保留检查点暂停，不缩小题数或跳过实验来凑结论。

## 1. LawBench与数据准备

LawBench完整基准包含20类中文法律任务，覆盖记忆、理解、应用；官方README按每类500条介绍，总体约1万条。它不是1万道同类型罪名分类题。本次只用 `3-3` 罪名预测的500条。上传工程中的 `LawBench` 对应 `data/crime_prediction/`，是原任务的200训练、50验证、100测试，共350条。

官方完整基准的罪名预测主指标是F1；本工程同时实现罪名集合完全匹配和F1。本次主指标仍使用原工程 `was_correct` 的完全匹配准确率，不偷偷切换指标。F1只作为附加诊断保存。一条案例可包含多个罪名，不能当作新的单标签选择题。

来源：
- https://github.com/open-compass/LawBench
- https://aclanthology.org/2024.emnlp-main.452/
- https://github.com/metaevo-ai/mce-artifact/blob/main/env/crime_prediction/data/README.md
- 固定源版本：`e30981bb3ff54c41571f222e0b23e92d27375388`
- 文件：`data/zero_shot/3-3.json`
- Git blob：`5f0d8864408a65182a556dc65e85801fdb968902`

数据划分固定为：

| split | 数量 | 用途与来源 |
|---|---:|---|
| train | 200 | 原训练样本；执行顺序与原seed42的单次shuffle完全一致 |
| score | 100 | 原50验证题 + 旧350题之外新增50题；所有候选排名用此分数 |
| feedback | 100 | 其余新增100题；D=0/50/100为该固定池的前D题 |
| audit | 100 | 原测试题；外部评估，不进入优化器历史 |

不要从别的19类任务抽题补罪名数据，不从旧test挪题，不使用one_shot版本当新题，不生成合成题来凑500条。100题评分比20题更细，但本次仍是小规模预实验；一分不自动等于稳健优势。

```powershell

```

脚本自动下载固定版本；网络受限时手动下载同一原始JSON，再执行：

```powershell

```

脚本执行以下检查：原文件500条；原350条逐题匹配；答案标签集合一致；350条之外恰好150个不同案件；最终四组互不重叠；D50包含于D100；不改变训练样本和顺序。新增150条先按固定种子20261003打乱，前50入score，后100入feedback。没有按模型表现筛题。

产物 `manifest_v3.json`、四个JSONL和 `data_audit.json` 置于外部评估目录。训练JSONL已经按执行顺序排列，加载时不能再shuffle。保留旧50题标记，便于单独报告新增50题评分结果。标签/文本匹配失败时暂停并报告，不自动模糊合并案件。当前包没有全量源数据或已生成的真实manifest；完整500题下载和匹配必须由本步骤成功完成后才能启动模型实验。

## 3. 代码修改要求

### 3.1 数据入口与评分

修改 `data/loaders.py` / `data/api.py` 支持读取新版manifest。复用原 `_load_lawbench` 的提示词包装、`罪名:`前缀处理与 `data/evaluators.py` 的评分逻辑；不要把原始instruction直接替换为另一套prompt。train/score/feedback/audit都必须走同一种包装。

在pilot模式显式接收manifest并按其顺序取题，不再通过修改原num_val或shuffle_seed选择题目。旧入口非pilot时保持可用；配置只启用LawBench。不要让通用benchmark工具静默读取原三个数据集，或在新实验中仍给“avg_val”计算三数据集平均。

### 3.2 保存逐题记录

修改 `inner_loop.py` 的 `evaluate_memory` 和结果保存路径。保留原聚合JSON字段，并另存score_traces、feedback_traces和外部audit_traces。每题至少包括run_id、candidate、round、phase、item_id、input、prediction、target、was_correct、metrics、调用ID及真实prompt/response或其受控存储位置。保留实际返回metadata；原始响应不存在就标缺失，不用解析后的答案冒充原始响应。

原 `MemorySystem.call_llm()` 已使用线程局部信息记录最后prompt；若候选一次预测多次调用模型，最后prompt不足以代表全部轨迹，需要在LLM层按item_id关联每个请求和响应。不能为补日志多请求一次模型，不能在多个线程间错配记录。

`val.json`只写score100题；extra成绩写feedback_usage/feedback_traces，不能混入val排名。每个json标注manifest_hash、code_hash、memory_hash、有效模型配置和缓存模式。原测试文件无逐题数据，旧截图不补作逐题数据。

### 3.3 反馈采集与执行顺序

追加一个evaluate-only入口，加载指定代码和其memory，以独立状态副本预测feedback池前D题；不调用learn_from_batch、不传答案给predict。每个候选/面板只采集一次。D=0明确跳过。

一条两轮轨迹的状态机：

1. 加载H0，执行score100；采集H0的D条feedback；生成本组可见起点报告。
2. proposer第1轮生成A/B；分别训练200、保存memory、评分100。
3. 从H0/R1A/R1B按score选优，保存round1检查点和此时累计成本；将audit任务交外部进程。
4. 只有准备第2轮时，才对R1A/R1B各补D条feedback；保留H0历史反馈，不重新采集它。
5. proposer第2轮读取全部本组合法历史，生成A/B；分别训练200、保存memory、评分100。
6. 从全部5个版本选优，保存round2检查点和累计成本；外部audit。
7. 结束。不为R2候选执行不会被下一轮使用的feedback。

这意味着一轮的新增feedback题次为D，两轮累计3D。末轮未执行反馈不是漏评，是本研究只为下一次更新购买反馈的定义。评分与audit各从训练后的保存状态的独立副本开始，不互相带入副作用。检查persistent memory差异；含答案的学习更新不得在score/feedback/audit中发生。

### 3.4 优化器可见范围

每条运行只携带公共框架、H0代码、其训练memory、允许的起点训练记录。清理复制记录中的旧done验证总分；不要复制原20轮summary、frontier、claude_sessions、其他候选代码或七张分析图。

修改 `.claude/skills/meta-harness/SKILL.md` 和 `render_task_prompt()`，明确提供train/score/feedback轨迹路径；score100题负责排名；允许模型诊断和修改代码，不允许它修改D/k/题单/评估器、不允许联网查公开测试答案或自行额外跑题。保持原A/B机制修改约定。记录工具读取过的反馈文件数和item_id可用时的访问范围，不把“文件存在”直接等同于“所有反馈都进入上下文”。

完整源500题、audit题/结果、未抽中的feedback及其他运行放在外部评估目录。采用可用的工具/文件访问白名单；只有提示与目录分离时，在报告中写“操作隔离”，不要宣称实现了OS级强隔离。生成harness运行在不含其他数据文件的评估工作区，不能读取评分答案或source原文件。

### 3.5 缓存、重试和断点

新增 `TEXT_CLASSIFICATION_LLM_CACHE_MODE=off|run`；off不读不写完整响应缓存；run要求显式独立空目录，不静默回退全局目录。实验1全部off；新进化用run且不同run不共享，续跑只用自己的目录。服务商前缀缓存按真实usage记录，不必关闭。

增加按阶段、候选、面板的完成标记；恢复时检查文件哈希，完成阶段不重做，不因run-name不同复用错误面板。候选代码和memory在评分后不可被优化器覆盖。

API临时错误最多3次带退避重试，费用累计。鉴权错误立即暂停，基础设施失败不能记成题目答错。候选逻辑错误经固定验收确认为无效时，记invalid及已发生成本，不无限生成直到凑出20个成功者；有效候选数和名义生成数分别报告。proposer失败保留日志并暂停，不能静默跳轮。不要在中途调用会finalize运行的 `meta_harness.py --test`。

### 3.6 成本与时间

LLM usage在train/score/feedback/audit阶段前后取差值，计数线程安全且阶段结束等待请求完成；优化器每次会话费用只记一次。每条usage事件拥有唯一ID，防止重启后重复求和。字段至少包含logical_calls、api_requests、cache_hits、input/output tokens、可用的服务商缓存token、reported/estimated_usd、来源、wall_seconds、失败重试、phase、run_id、candidate。

C(T)为H0的新评分、已经用于后续更新的feedback、proposer、新候选train/score的累计成本。H0旧memory历史构建费用为共享C0另列。audit及实验1为研究测量费用，单列且不得回流选优。记录实验实际总支出（包括重复、审计）与每条方案的算法成本两种口径。这里报告费用不是订阅现金账单。

## 5. 实验1：冻结重评与评分题数诊断

**目的：** 测量相同harness的执行波动，判断后续3—5个百分点差异是否值得解释。

**原理：** 不改代码和memory，只重新执行相同题目；额外离线抽样检查20/50题评分是否容易排错版本，不增加模型成本。

**任务：** R4B `confusion_disambiguation_memory`、R7A `adaptive_tokenizer_confusion_memory`、R12B `discriminative_similarity_memory`，每个加载自己的LawBench memory，重评2次；每次100题score+100题audit，共1200次题目预测，不训练、不生成候选。

**步骤：**
1. 三个代码/memory记录hash，六个评估使用独立状态及off缓存。
2. 每次先后评估score和audit（状态互不污染），保存逐题结果。
3. 列出每个版本两次score、audit、差值、正确集合变化、API用量和时间。
4. 固定取第一次score结果，从100题中随机无放回抽20/50题各1000次，同一次抽样对三版本使用相同题目，记录与完整100题排名的逆序率和同分比例。100题只是本次参考，不是真实能力真值。不根据结果改题单。
5. 定义噪声参照J=max(三个版本两次audit分的绝对差)，单位pp；定义预实验值得关注的变化阈值δ=max(3pp,J)。这是预先规定的筛查门槛，不是显著性检验。
6. H0参考测试成绩S0取R4B两次audit平均；以后交付H0时统一使用此参考。三个冻结版本完整诊断结果都不进入proposer历史。

**输出：** noise_summary.csv、panel_stability.csv、noise_reference.json。

**时间：** 按最多两组冻结重评同时运行，预留0.5—1.5小时；新代码验收时间另计。

## 6. 实验2：一轮反馈量对照

**目的：** 在同一起点和同一次修改机会下，额外100题日志是否提高候选质量及实际交付表现。

**原理：** 唯一主动改变的是可见extra反馈量D；其他设置和评分题固定。重复a/b用于检查方向是否稳定。

**任务：** D0_a、D0_b、D100_a、D100_b各进化1轮，每轮2候选，共4次proposer会话和8个候选。

**步骤：**
1. 各run从同一H0 snapshot开始，用自己的run缓存评分100题。给D100起点补100题反馈；D0不补；全部基于相同训练历史。
2. 在反馈准备完成后调用第1轮proposer。不能先生成候选，再补起点反馈。
3. 子代A/B各自从空memory跑200题train，保存状态，跑100题score。
4. 按score在H0/A/B中选优，保存round1_checkpoints以及此时C，不补子代extra。
5. 外部程序对8个新候选各audit100题，结果隐藏。选中H0用S0；选中子代用其audit成绩。
6. 汇总各run两个子代分数、子代均值、selected、S、C、有效/失败候选数及反馈读取记录。

**输出：** round1_candidates.csv、round1_comparison.csv。报告D100-D0在a、b两次对照的差值及平均值，并区分“生成质量”与“选中质量”。

**时间：** 两条轨迹并发、同轨迹候选串行，预留3—5小时，包括训练评分和外部audit，不包括程序开发。

## 7. 实验3：追加一轮，形成四格T×D关系

**目的：** 比较多一次串行进化的收益，以及增加反馈对第二轮的帮助。

**原理：** 续跑实验2，不另从头跑；T=1/2、D=0/100构成2×2网格，每格2次运行。N=2T，不单独扫N。

**任务：** 原四条run各追加第2轮，新增8个候选；本实验前后共16个新候选。

**步骤：**
1. 核验round1快照、候选hash与费用已保存。
2. 给R1A/R1B各补本组D题extra，加载其保存memory，不训练；H0已有反馈不重采。
3. 启动第2轮proposer读取本组所有合法历史，生成两个新子代；各train200+score100。
4. 在H0及两轮4候选中按score选优，保存round2_checkpoints和C，不给末轮补extra。
5. 外部audit第2轮8个新候选。交付历史版本时复用同一audit结果，不反复重测使曲线改变。
6. 生成四格表：每格列a/b的S、C及均值，不能只列均值。
7. 计算每个D下S(T2)-S(T1)；每个T下mean S(D100)-mean S(D0)。同时列对应费用变化。
8. 在已测配置上列成本—性能非支配方案；需要同预算视角时，用预先声明的共同预算在各轨迹检查点中选择不超预算的最后完整点，不在两轮之间虚构中间harness。只称“已测配置中的取舍”，不宣称全局最优。

**输出：** all_candidates.csv、checkpoint_summary.csv、grid_summary.csv、cost_performance.png、round_gain.png。主图S为score选中者的audit表现；事后audit最高只作独立诊断，不能画成实际交付曲线。

**时间：** 两轨迹并发约3—5小时。D100两轮累计extra300题/运行，D0为0。

## 8. 实验4：事前预测D50并验证

**目的：** 检验用少量已测配置能否预测一个新配比，避免只画事后曲线。

**原理：** 只用D0/D100的两轮结果预测中间D50；冻结预测后，才启动D50_c的新轨迹。

**任务：** D50_c从H0独立进化2轮，k=2，共4个新候选和2次proposer会话。

**步骤：**
1. 计算两轮D0和D100的平均S与C；预测D50的S、C各为两端均值。
2. 同时保存两个简单成绩基线：忽略D直接用两轮D0平均S；忽略进化直接用S0。
3. 在holdout开始前写prediction_before_run.json，保存输入文件hash、时间、三种预测和费用预测。不在看到D50结果后重拟合、改指标或阈值。
4. 按同样状态机执行D50_c两轮：起点extra50；第一轮2个候选各extra50；末轮不补；累计extra150。
5. 所有新候选audit，选中者按score确定；核对最终S和C。
6. 计算三种成绩预测的绝对误差（pp）及费用相对误差；输出原预测与真实结果并排表。

**输出：** prediction_before_run.json、prediction_check.csv、holdout_summary.json。可在执行前记录成本性能上“D50预计是否值得选”，事后核对，不额外拟合一个大模型。

**时间：** 单条轨迹两轮约3—4.5小时。它是一个独立新运行上的中间配比插值验证，不是跨benchmark或大轮数外推。

## 9. 自动分析与结论规则

所有分析先确认数据完整、模型/代码/manifest一致、没有audit泄露、阶段成本不重计。任何验收失败，先标“实验执行无效/不完整”，不能用分数作科研结论。

### 9.1 噪声与方向

J和δ来自实验1。对于T或D对照，报告两次对照各自差值、均值、最大最小值。两次同方向且平均变化绝对值≥δ，标“有初步可复现的正/负作用”；方向不一致或幅度不足，标“当前规模未分辨出稳定作用”。不要把两次重复写成统计显著性证明，也不要将40个旧候选或同一轨迹两节点当独立样本。

逐题报告增加答对、原本答对变错、净增。允许补充固定候选间的题目配对bootstrap，但必须说明它只估计固定候选在这些题目上的不确定性，不能替代优化器重复。1000次离线重采样不是1000次独立进化。

若D改善子代均值但交付分数不改善，报告“生成改善信号与选择结果分离，需检查评分选择”，不要直接宣称全是选优故障。评分分数升高、测试不升高也必须报告。

### 9.2 未测点预测

若两端平均S差异不足δ，D50即使接近中间值也只记“平坦区预测接近”，不能算使用D获得增量预测能力。

若端点作用可分辨，且D50中间值预测误差≤5pp，并比两个简单基线的误差都至少小1pp，记“单个未测配比预测有正面初步证据”；否则记“该简单预测未优于基线”或“预测偏离”。这是事先约定的预实验筛查标准，不是成功率保证。

费用单独判断预测误差，不把费用容易预测等同于性能可预测。一次D50不能验证期望曲线可靠性；报告明确要求下一阶段独立重复，而不事后悄悄多跑到命中。

### 9.3 给导师的最终结论必须落到以下一种

| 观察结果 | 结论与下一步 |
|---|---|
| T、D有可分辨作用，D50预测优于基线 | 有继续做二维性能—成本研究的初步证据；扩展轮数、重复和独立任务 |
| T、D有作用，但D50预测不佳 | 资源配比问题存在，当前简单预测形式不足；先增加少量配置再选函数 |
| 只有T或只有D的作用可分辨 | 当前设置先围绕有信号的轴扩展，保留另一轴边界，不宣称二维定律成立 |
| 子代有改善、交付无改善 | 优先排查候选选择与评分稳定性，不能把交付平台直接归咎于缺少进化 |
| 两者都未超过噪声或经常方向相反 | 这次预实验没有给出足够支持；不继续用这4格强行拟合scaling law |

不能要求agent无论结果如何都写“可行”。本次从R4B只追加两轮，是局部预实验，不证明长期停止点、普适幂律或跨任务泛化。明确结论可以是“证据不足”，但必须指出不足具体来自噪声、作用幅度、执行错误还是预测失效。
