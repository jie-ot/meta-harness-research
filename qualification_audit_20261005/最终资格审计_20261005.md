## 5. 静态调用图、真实调用数、缓存与恢复

候选生成链：

`run_evolve → render_task_prompt → propose_claude → Claude CLI 多轮模型/tool交互 → 一次 session 产出 A/B 两候选 → import 验证 → benchmark`。

一次 proposer session 同时产生两个候选，不是“每候选一次模型调用”。例如 D0_a 第 1 轮保存 21 个 logical message、22 个 API request。

评价链：

`worker.execute → load_pilot_split → load_memory_system → set_state(固定训练 memory) → evaluate_memory → 每题 memory.predict → MemorySystem.call_llm → LLM.__call__ → ProviderLLM.generate/_generate_one → cache 或 litellm completion`。

项目主入口没有统一的 Q1/Q2/Q3 三次 API 阶段，不能按固定三次乘算。真实例子：

- `confusion_disambiguation_memory.predict` 每题 1 次 LLM，`learn_from_batch` 不调用 LLM；新 memory 训练 200+score 100 至少 300 logical calls，再 audit 100，合计至少 400，retry/cache 另算。
- `reflexion_lesson_memory` 每题 predict；若错误且 prediction 非空，还会生成 lesson，所以训练 200 题可超过 200 calls。
- `canonical_charge_lexicon_memory` 空答案时追加调用；已有 train/score/audit 为 221/105/113 logical calls。
- `act_decomposition_union_memory` 按 act 分段多次调用并可能 fallback；已有 100 题 audit 为 238 logical calls、234 API requests、4 cache hits。

pilot 每个 logical call 最多首发+3 retry，litellm 内部 retry 明确关闭；401/403、不可重试错误或第 4 次失败即停，不自动换模型（`pilot/llm.py:259,319`）。原复现 provider 外层最多 6 次，benchmark 可重启整个 job 最多 3 次（`reference_examples/text_classification/llm.py:223`、`benchmark.py:76`），所以 logical call、API request 和完整 job 次数不能互换。

缓存 key 含版本、规范化 model、api_base、system prompt、prompt、kwargs，但不含 run/candidate/split/item/代码 hash。原默认共享 `~/.cache/text-classification/litellm`，可能跨 run 复用相同 prompt；pilot 按 run 隔离到 `external/caches/<run>`，但同一 run 内不同 candidate/phase 仍可能命中。独立复测必须预先规定 cache-off 或全新命名空间。

LawBench 每个新 candidate 从空 memory 重新训练；代码 parent 不继承 parent 训练状态。共同 H0 是明确复制的既有 R4B 训练 memory。原恢复按完成状态、签名和文件 hash 复用；train 有逐 step state，eval 有逐 item prediction。搜索后修复、失败重启、共享 H0 和 cache hit 都必须保留为 censoring/依赖来源。
